## 1. 新手直接复制：老板带员工干活

> 用 work-together 帮我完成【你的目标】。你当老板，先检查当前项目，帮我写清做什么、哪些东西不能动、怎样才算完成，再给员工分活。能独立做的同时做，需要前面成果的排在后面。员工交货后由你亲自检查，合格后汇总，告诉我成果在哪里、检查结果和遗留问题。先在本地完成，不接 Gitee，不发布、不推送。

不必先手写配置。老板会根据项目准备；缺少安装、登录或业务信息时再引导你处理。想看进展，可以说「现在谁在干什么，哪些等检查，有没有需要我处理的事？」。

## 2. 需要指定分工时使用的详细提示词

**适用场景**：任务可拆成独立验收包，由当前聊天所在的 AI（Codex、ZCode、Qoder 或 WorkBuddy）负责规划与验证，指派其他工具的桌面会话在同一项目目录后台执行，并能从桌面查看过程。

**提示词：**

请调用 work-together skill 完成本次任务（Codex 里用 `$work-together`；ZCode、WorkBuddy 按各自的技能调用方式）。

主持方：{当前聊天所在的工具，写入 plan.json 的 coordinator，缺省 codex}
执行器：{默认 auto；或指定 zcode、qoder-global、qoder-cn、workbuddy-global、workbuddy-cn，自动排除老板同族。缺额度或不可用时按 Skill 候选规则切换；结果未知先查原会话，不重复派发}
共享项目目录：{绝对路径}
目标：{本次要完成什么}
输入：{现有文件、资料和必要上下文}
不可修改的边界：{文件、行为、账号、发布限制}
交付物：{明确的文件或应用状态}
验收条件：{逐条可观察的完成标准}
最大并发：{默认 2}

默认模型策略按 SKILL.md 核对：ZCode 精确 GLM-5.3-FlashX，其余候选需满足当前明确零费率等要求；没有合格候选就报告，不自动改用收费模型。像老板按预算找员工，不要求用户先学会费率表。权限设置遵循用户要求与执行器能力，完全访问不扩大本次业务授权。

由你作为老板，按「写订单 → 排班分活 → 员工开工 → 检查交货」推进（分别对应 Spec → Plan → Exec → Verify）。先读真实现场与已有修改，把目标、边界、交付物、验收方法和恢复入口写成短 Spec；再规划依赖、关键选择和风险，拆成有文件归属、证据要求的小执行包。不要把同一个完整需求同时扔给多个窗口。

你主要负责 Spec、Plan 和独立 Verify，所选桌面员工负责 Exec。通过真实桌面会话派发，让多个无依赖且文件归属不重叠的包在后台同时开工；重叠文件、共享构建产物、依赖安装、Git 操作必须串行协调。执行者仍须判断现场差异，在边界内调整，超出边界再提出问题。

主对话保持清爽：完整试错和终端日志保留本地，不贴几百行输出；你持续接收紧凑状态，汇总哪些会话工作中、待验收、失败或需要我介入。每包使用桌面原生待办更新进度；你的总计划随真实验收结果推进。需要我回应时，给我一张简短回顾卡：本轮成果、阻塞点、需我回答的具体问题、会话位置和回答后的下一步。权限与问题由我在对应桌面会话处理。

执行者结束只表示交回，不能直接标为通过。你读取真实产物并独立验证，按 Spec 将测试退出码、文件、截图、控制台或应用后台状态等证据逐条对应；失败在原会话修复。所有包验收通过后，整洁汇总交付路径、结果、证据和遗留问题。中断时保存 sessionId 和状态，恢复先查询原会话，避免重复执行或覆盖修改。

先检查候选工具的桌面桥是否可用。不得把命令行执行冒称为桌面实时会话，也不得承诺仅靠提示词实现宿主未提供的跨回合自动唤醒。没有直接会话接口或文章无法读取时，明确说明真实缺口并继续可完成的工作。

派发后自动打开本次项目与目标 session，确认侧栏选中该会话、正文出现本次任务包标记，再报告“桌面过程可见”。不能用旧 smoke 测试会话代替证明。若显示失败，保留正在运行的原 session，执行 open 修复显示，不重复派发；需要我介入时直接定位到需要回应的会话。

## 3. 恢复已有协作任务（旧 workflow 模式）

**适用场景**：Codex 或执行器中断，需要接着已有桌面会话推进。

**提示词：**

请使用 $work-together，读取 {项目目录} 的 SPEC.md、PLAN.md 和 .work-together/state.json。先核对当前进程、已有修改、会话状态与证据，再恢复原执行器和原 sessionId。结果未知的包先查明，不重复派发。继续独立验收并更新总计划；需要我介入时给出回顾卡。
