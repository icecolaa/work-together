# 反模式与高频问题（FAQ）

按症状查找。所有条目都来自真实运行中踩过并验证过修复方式的问题。

## 派发与可见性

**Q：调度器显示任务已派发，但桌面里找不到会话？**
先看 `status` 里该包的 `visibility.confirmed`。可见性需要三要素齐备：正确项目 + 选中目标 session + 正文出现 `协作任务包：包ID`。缺任一都算未确认。修复方式：在实际任务项目根目录执行 `node <runner> open <包ID>`——它只重新定位已有会话，**不重发消息、不重建会话**。显示失败 ≠ 重新派发：任务可能已在运行，重派会造成双会话。旧 smoke 会话被选中不算数。

**Q：能不能把任务派给主持方自己（engine = coordinator）？**
不能，调度器直接拒绝。主持方就是写 Spec/验收的聊天，Exec 必须是其他工具的桌面会话；单工具能完成的任务不需要本 skill。`both` 表示"全部可指派的工具"，自动排除主持方。

**Q：两个包要写同一个文件，能并行吗？**
不能。归属交叠的包由调度器自动串行（`canStart` 文件重叠检查，含大小写与目录层级）。真正会互相冲突的还有：共享构建输出、依赖安装、端口、数据库、Git index——计划者必须把这些分配唯一写入责任或改为依赖串行。文件归属是协作约定，不是操作系统沙箱。

## 状态与验收

**Q：执行器说"完成了"，能直接算通过吗？**
不能。执行结束只是 `exec_done`（交回），必须主持方逐项核对真实产物、diff、测试退出码后执行 `verify` 才是 `verified`。不得把执行者自测称为验收通过。

**Q：verify 报退出码 2，"存在归属清单外变更"？**
运行前后有文件指纹比对，任何归属清单外的增/改/删都会阻断验收——**包括主持方/用户自己迟写入的文件**（比如调度器启动后才把笔记放进项目根目录）。处理：查明每个变更的来源；确认无害后，把用户侧材料移入 `.work-together/`（不参与指纹）或删除。这是事后检测，不是写入拦截，也不会自动回退。

**Q：包状态变成 unknown / failed 怎么办？**
unknown = 执行结果未知（如连接断开）。禁止重派：先到原桌面会话查最终状态；有 sessionId 时用 `run plan.json --resume` 恢复（复用原会话 ID）。failed 时按 skill 流程**退回原会话修复**——向同一 sessionId 发修正指令，必须用**新的请求 ID**（复用旧 ID 会被缓存吞掉）；修好后产物重新逐字节验收。

**Q：取消一个包会发生什么？**
`cancel <包ID>` 把停止请求送到原会话并写 controls 记录；必须确认桌面最终状态后再释放该包的文件归属。调度器不删除原会话、不做 git reset、不清理用户修改。

## 环境与启动

**Q：doctor 失败 / 调试端口不可用？**
先跑 `start-desktops.ps1 -Engine both`：健康实例直接复用；未开调试端口的运行实例会被自动退出并重启（托盘进程超时后强杀同安装路径进程）。当前项目有运行中任务时默认保护现场，明确要中断加 `-ForceRestart`。端口仅本机（ZCode=19331、WorkBuddy=19332），不要转发外网。桌面桥绑定已验证版本（ZCode 3.15.3 / WorkBuddy 5.7.6）；**应用升级后 doctor/run 必须明确失败**，这是设计行为——先修适配，不许假报成功。

**Q：headless 主持（codex exec / WorkBuddy 命令沙箱）里启动调度器总失败？**
这些沙箱不承载长驻进程：codex exec 回收分离子进程；WorkBuddy 在策略层拦截 WMI/Start-Process。分工应是：**调用方（用户或交互式宿主会话）启动调度器，主持会话只做 Spec/Plan/监控/验收**。注意 WorkBuddy 沙箱的后台任务机制能另起调度器，但会与已有实例撞 `runner.lock`（单调度器约束，属预期）。本机经 MSYS 调用时 `Start-Process -WindowStyle Hidden` 会以退出码 127 静默失败，分离启动用 WMI `Win32_Process.Create` 或宿主后台进程。

**Q：同目录能同时跑两个调度器吗？**
不能。`runner.lock` 保证单实例；意外退出会残留锁，`--resume` 会先确认旧进程已退出再复用会话。

## 计划与模型

**Q：跑到一半需求变了，直接改 plan.json 行吗？**
不行。恢复时校验 planHash，计划变化会被拒绝——禁止静默更换文件归属或依赖。正确做法：等本轮收尾（或 cancel），归档 `.work-together` 后按新计划开新一轮。

**Q：怎么选模型？**
主持方不指定时：ZCode 固定 GLM-5.3-Flash（完全访问 yolo），WorkBuddy 按本机费率列表动态选**零费率**模型（Step-5-Preview 优先），无零费率时选最低已知费率并在汇报中说明。**Auto 和空费率不代表免费**。主持方指定的模型不可用时明确失败，不静默换模型。

**Q：执行器能写共享记忆/工作日志吗？**
不能。执行器禁止写 `.workbuddy-ai/memory`、`MEMORY.md` 等共享文件（越界写入会被指纹检测抓到并阻断验收）；需要记忆时在最终回复里交给主持方统一整理。

## 外部驱动

**Q：用脚本驱动 `Desktop.create` 时报 "cwd lost its path separators"？**
cwd 被多层字符串转义吃掉了路径分隔符。从外部传路径应走 argv/env 等免转义通道；注意 `node -e` 模式下附加参数从 `process.argv[1]` 开始。
